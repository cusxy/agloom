# A1: Web-Only (dist + README)

## Описание

Пакет содержит только скомпилированный код и README. Документация
размещается на внешнем ресурсе (GitHub, docs site). Это доминирующий
подход в экосистеме Node.js CLI.

## Кто использует

eslint (2.9 MB, 418 files), prettier (8.6 MB, 56 files), turbo (47 KB, 5 files),
vercel (8.3 MB, 91 files), tsx (432 KB, 50 files), esbuild (144 KB, 7 files),
vitest (1.9 MB, 114 files), @biomejs/biome (670 KB, 18 files).

8 из 10 исследованных production CLI используют этот подход.

## Реализация

```json
{
  "files": ["dist"],
  "bin": { "tool": "dist/cli.js" }
}
```

README автоматически включается npm при публикации. Некоторые пакеты
дополнительно включают JSON Schema для IDE-интеграции:
turbo — `schema.json` (31 KB), biome — `configuration_schema.json` (508 KB).

## Оценка по критериям

### C1: Zero-config доступность — Low

После `npm install -g` доступен только `--help` (генерируемый CLI-фреймворком)
и README.md в `node_modules/`. Пользователь должен перейти на website
для полной документации. `man <tool>` не работает.

### C2: AI-совместимость — Low

AI-инструменты могут прочитать README, но он обычно содержит минимум
информации (esbuild — 175 bytes, vitest — 256 bytes). Без AGENTS.md
или CLAUDE.md в пакете AI-агент не получает инструкций по использованию.

### C3: Maintenance burden — Minimal

Нулевая дополнительная нагрузка — документация живёт отдельно от пакета.
Это главное преимущество подхода.

### C4: Package size impact — Minimal

Только скомпилированный код. Пакет остаётся максимально компактным.

### C5: Discoverability — Low

Пользователь зависит от `--help` (часто ограничен) и внешних ресурсов.
Без интернета полная документация недоступна.

### C6: Single-source потенциал — N/A

Не применимо — в пакете нет документации, которую можно генерировать.

## Плюсы

- Минимальный размер пакета.
- Нулевая дополнительная поддержка.
- Доминирующий pattern — пользователи ожидают web-документацию.

## Минусы

- Документация недоступна offline после `npm install`.
- AI-инструменты не получают контекста о пакете.
- `man <tool>` не работает — нарушает Unix conventions.
- README часто слишком краткий для полноценной справки.

## Контекст применимости

**Оправдан**, когда: CLI является тонкой обёрткой (turbo, esbuild);
документация объёмная и лучше подходит для website; пакет минимизирует
размер tarball (e.g., thin wrapper + optionalDependencies).

**Не оправдан**, когда: целевая аудитория активно использует AI-инструменты;
CLI имеет сложный набор команд и опций; требуется offline-доступность.
