# Контент и правила

## 1. Централизованное управление правилами

### Ruler

Директория `.ruler/` в корне проекта содержит `.md`-файлы с инструкциями.
`RuleProcessor.ts` обнаруживает все markdown-файлы в директории
и конкатенирует их в единую строку. Порядок определяется файловой системой.

```text
.ruler/
  coding-standards.md
  architecture.md
  testing.md
```

Все файлы объединяются, и каждый агент получает одинаковый результат.

### Agloom

Директория `.agloom/` содержит `AGLOOM.md` (и опционально `AGLOOM.local.md`)
с YAML frontmatter и Markdown body. Файлы могут располагаться рекурсивно
в поддиректориях проекта (discover сканирует весь проект).

```text
.agloom/
  AGLOOM.md          # frontmatter + body
  config.yml
src/
  module-a/
    AGLOOM.md        # контекст-специфичные инструкции
```

Ключевое отличие: Agloom поддерживает per-agent секции через
`<!-- agent:claude -->` / `<!-- /agent:claude -->` HTML-комментарии
и frontmatter overrides. Разные агенты получают разный контент.

### Плюсы Ruler

- Простота: любой `.md`-файл в `.ruler/` автоматически включается.
- Нулевой синтаксис: чистый Markdown без frontmatter.
- Низкий порог входа: пользователь создаёт `.md`-файл и запускает `apply`.

### Минусы Ruler

- Нет per-agent контента: все агенты получают идентичный текст.
- Нет метаданных: отсутствует frontmatter для описания, типизации.
- Порядок файлов зависит от файловой системы (недетерминирован).

### Плюсы Agloom

- Per-agent filtering: Claude получает секции для Claude, AGENTS.md --
  секции для agentsmd.
- Frontmatter: метаданные, переменные, описание.
- Детерминированный discover: сканирование рекурсивное, порядок по пути.

### Минусы Agloom

- Более сложный синтаксис: HTML-комментарии для agent-секций.
- Один файл `AGLOOM.md` в корне -- менее гибко, чем N файлов.

## 2. Concatenation markers

### Ruler

При объединении файлов Ruler вставляет HTML-комментарий
`<!-- Source: relative/path.md -->` перед содержимым каждого файла.
Это позволяет отследить происхождение каждой секции в сгенерированном файле.

```markdown
<!-- Source: .ruler/coding-standards.md -->

# Coding Standards

...

<!-- Source: .ruler/testing.md -->

# Testing Guidelines

...
```

### Agloom

Agloom не использует конкатенацию и не добавляет source markers.
Содержимое трансформируется (frontmatter парсится, agent-секции
фильтруются, переменные интерполируются), и результат записывается
как единый файл. Происхождение не отслеживается в выходном файле.

### Плюсы Ruler

- Трассируемость: пользователь видит, из какого файла пришла инструкция.
- Помощь при отладке: если агент некорректно интерпретирует правило,
  можно быстро найти исходник.

### Минусы Ruler

- Увеличивает объём сгенерированного файла.
- HTML-комментарии могут быть интерпретированы некоторыми агентами как контент.

### Плюсы Agloom

- Чистый output: нет служебных маркеров в генерируемых файлах.
- Трансформация: output -- не механическая склейка, а обработанный контент.

### Минусы Agloom

- Нет трассируемости: при ошибке в сгенерированном файле непонятно,
  какой AGLOOM.md файл является источником.

## 3. Nested Rule Loading

### Ruler

Флаг `nested` в `ruler.toml` или CLI (`--nested`) активирует поиск
всех `.ruler/` директорий рекурсивно. Каждая директория обрабатывается
независимо: свои правила, свой `ruler.toml`, свой набор агент-файлов.

```text
monorepo/
  .ruler/            # глобальные правила
    ruler.toml
    global.md
  packages/
    api/
      .ruler/        # правила для API
        api-rules.md
    web/
      .ruler/        # правила для web
        web-rules.md
```

Каждый `.ruler/` генерирует файлы относительно своего parent-каталога.
Глобальный `.ruler/` -- для корня, `packages/api/.ruler/` -- для `packages/api/`.

### Agloom

Agloom обнаруживает AGLOOM.md рекурсивно, но обрабатывает все файлы
в одном pipeline. Нет концепции независимых scope с собственными
конфигурациями. `config.yml` один на весь проект.

### Плюсы Ruler

- Монорепо-поддержка: каждый пакет может иметь свои инструкции.
- Независимые конфигурации: разные агенты для разных пакетов.

### Минусы Ruler

- Сложность: N `.ruler/` директорий = N независимых конфигураций.
- Риск конфликтов: если вложенный `.ruler/` переопределяет агентов.

### Плюсы Agloom

- Единый pipeline: все AGLOOM.md обрабатываются вместе.
- Рекурсивный discover уже работает для per-directory инструкций.

### Минусы Agloom

- Нет независимых scope: невозможно указать разные адаптеры для
  разных частей монорепо.
- Один `config.yml` -- ограничение для гетерогенных монорепо.

## Рекомендации

- **Concatenation markers** -- рассмотреть добавление опционального
  source-комментария в output для трассируемости (low priority).
- **Nested rules** -- для монорепо-пользователей существенная возможность.
  Реализация потребует поддержки per-directory `config.yml` или аналога
  (medium priority).
