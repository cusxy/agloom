# type: agent

**Назначение.** Определение агента для циклических скиллов-оркестраторов.
Агент участвует в паре «исполнитель → reviewer» с quality gate между фазами.
Содержит контракт (header) и инструкции (implementation),
управляющие поведением LLM-агента.

## Front matter

Агенты используют собственный формат front matter, отличный
от документационного:

| Поле          | Тип    | Обязательность | Описание                |
| ------------- | ------ | -------------- | ----------------------- |
| `name`        | string | ТРЕБУЕТСЯ      | Идентификатор агента    |
| `model`       | string | ТРЕБУЕТСЯ      | Модель LLM              |
| `description` | string | ТРЕБУЕТСЯ      | Краткое описание агента |

## Структура

Определение агента разделено на **header** (контракт) и **implementation**
(детали). Полное описание обязательных и рекомендуемых секций —
[agent-protocol.md](../cycling/agent-protocol.md) → «Структура определения агента».

## Тон и стиль

Описания агентов используют второе лицо (директивные обращения
к агенту с RFC 2119 keywords), потому что instruction-tuned модели
оптимизированы следовать директивным инструкциям во втором лице.

Каждый запрет ДОЛЖЕН содержать обоснование: «ЗАПРЕЩАЕТСЯ \<действие\>,
потому что \<причина\>».

## Валидация

| #   | Правило                                                          | Тип           |
| --- | ---------------------------------------------------------------- | ------------- |
| A1  | Front matter содержит `name`, `model`, `description`             | Структурное   |
| A2  | Присутствуют секции DoR и DoD                                    | Структурное   |
| A3  | Присутствует секция «Общие документы» со ссылками                | Структурное   |
| A4  | Присутствует секция «Входные параметры» с типами scope и context | Структурное   |
| A5  | Присутствует секция «Артефакты» (для исполнителей)               | Структурное   |
| A6  | Присутствует секция «Нештатные ситуации» (для исполнителей)      | Структурное   |
| A7  | DoR/DoD оформлены как чеклист (`- [ ]`)                          | Структурное   |
| A8  | В конце файла указан `returnTo`                                  | Структурное   |
| A9  | Каждый ЗАПРЕЩАЕТСЯ имеет обоснование (`потому что`)              | Семантическое |
| A10 | Пункты DoR/DoD бинарны (да/нет)                                  | Семантическое |
| A11 | Пункты DoR/DoD атомарны (одно условие)                           | Семантическое |
| A12 | Инструкции написаны во втором лице                               | Семантическое |
