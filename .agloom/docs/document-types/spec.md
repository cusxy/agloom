# type: spec

**Назначение.** Спецификация модуля — описание поведения системы,
из которого выводятся тесты и реализация. Единственный источник истины
для фаз test и implement цикла spec-driven development.

## Front matter

Общие поля — см. `index.md` → «Документационный front matter».

Дополнительные поля:

| Поле      | Тип      | Обязательность | Описание                               |
| --------- | -------- | -------------- | -------------------------------------- |
| `status`  | enum     | ТРЕБУЕТСЯ      | Статус жизненного цикла                |
| `maps_to` | string[] | МОЖЕТ          | Пути к коду, реализующему спецификацию |

### Статусы

| Значение      | Описание                                                     |
| ------------- | ------------------------------------------------------------ |
| `draft`       | Спецификация в процессе написания, не готова к имплементации |
| `ready`       | Готова к имплементации (или имплементация не завершена)      |
| `implemented` | Код полностью соответствует спецификации                     |
| `outdated`    | Спецификация устарела, требует обновления                    |

## Структура

Спецификация ТРЕБУЕТСЯ содержать:

1. Стандартную вставку RFC 2119 после front matter.
2. Операции в формате, описанном в [spec-format.md](../../skills/spec-cycle/docs/spec-format.md):
   каждая операция содержит секции Вход, Поведение, Расширения, Результат.

## Тон и стиль

Спецификации пишутся в третьем лице. Обращения ко второму лицу
ЗАПРЕЩАЮТСЯ, потому что третье лицо устраняет неоднозначность адресата
и делает спецификацию пригодной для механического извлечения тестов.

## Валидация

| #   | Правило                                                                  | Тип           |
| --- | ------------------------------------------------------------------------ | ------------- |
| S1  | Front matter содержит `type: spec`                                       | Структурное   |
| S2  | Front matter содержит `status` с допустимым значением                    | Структурное   |
| S3  | Документ содержит стандартную вставку RFC 2119                           | Структурное   |
| S4  | Каждая операция содержит секции Вход, Поведение, Расширения, Результат   | Структурное   |
| S5  | Нет маркеров `[NEEDS CLARIFICATION]` при `status: ready/implemented`     | Структурное   |
| S6  | Текст написан в третьем лице (нет обращений на 2-е лицо или императивов) | Семантическое |
| S7  | Ключевые слова RFC 2119 используются по назначению                       | Семантическое |
| S8  | Каждый шаг поведения — одно наблюдаемое действие (нет «и»)               | Семантическое |
