# Типы документов

Каждый markdown-файл проекта имеет тип, определяющий его назначение,
структуру и правила валидации. Тип указывается в YAML front matter.

## Front matter

Формат front matter зависит от категории файла:

| Категория    | Расположение                | Поля front matter                |
| ------------ | --------------------------- | -------------------------------- |
| Документация | `docs/`, `.agloom/docs/`    | `summary`, `description`, `type` |
| Агент        | `.agloom/agents/`           | `name`, `model`, `description`   |
| Скилл        | `.agloom/skills/*/SKILL.md` | `name`, `description`            |

### Документационный front matter

| Поле          | Тип      | Обязательность | Описание                                       |
| ------------- | -------- | -------------- | ---------------------------------------------- |
| `summary`     | string   | ТРЕБУЕТСЯ      | Заголовок документа                            |
| `description` | string   | ТРЕБУЕТСЯ      | Краткое описание содержимого (1-2 предложения) |
| `type`        | enum     | ТРЕБУЕТСЯ      | Тип файла (см. таблицу ниже)                   |
| `status`      | enum     | Только `spec`  | Статус жизненного цикла                        |
| `relates`     | string[] | МОЖЕТ          | Пути к связанным документам                    |
| `maps_to`     | string[] | Только `spec`  | Пути к коду, реализующему спецификацию         |

### Агентский front matter

Агенты используют собственный формат front matter. Подробности — `agent.md`.

### Скилловый front matter

Скиллы используют собственный формат front matter. Подробности — `skill.md`.

## Типы

| Тип        | Категория    | Описание                                                  |
| ---------- | ------------ | --------------------------------------------------------- |
| `index`    | Документация | Общее описание концепции папки, пререквизит для остальных |
| `spec`     | Документация | Спецификация модуля с жизненным циклом                    |
| `doc`      | Документация | Информационный документ                                   |
| `research` | Документация | Исследование и анализ принятых решений                    |
| `manifest` | Документация | Реестр компонентов системы                                |
| `agent`    | Агент        | Определение агента spec-cycle                             |
| `skill`    | Скилл        | Определение скилла-оркестратора                           |

## Общие правила валидации

| #   | Правило                                               | Тип         |
| --- | ----------------------------------------------------- | ----------- |
| G1  | Файл содержит YAML front matter                       | Структурное |
| G2  | Front matter содержит все обязательные поля категории | Структурное |
| G3  | Значение `type` входит в перечень типов               | Структурное |
| G4  | Пути в `relates` разрешаются в существующие файлы     | Структурное |
| G5  | Пути в `maps_to` разрешаются в существующие пути      | Структурное |
