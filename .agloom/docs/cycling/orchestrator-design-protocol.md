# Протокол создания и валидации skill-оркестраторов

Design-time протокол для создания, изменения и валидации SKILL.md файлов.

- Общие правила (RFC 2119, тон, стиль, правила написания): [cycle-design-protocol.md](cycle-design-protocol.md).
- [Runtime-протокол](orchestrator-protocol.md) (запуск, мониторинг, возобновление агентов).

## Структура SKILL.md

Каждый файл skill-оркестратор (`.agloom/skills/<name>/SKILL.md`) ДОЛЖЕН
содержать следующие секции:

| Секция              | Обязательность | Описание                         |
| ------------------- | -------------- | -------------------------------- |
| YAML front matter   | ТРЕБУЕТСЯ      | `name`, `description`            |
| Вводный абзац       | ТРЕБУЕТСЯ      | Роль оркестратора                |
| Общие документы     | ТРЕБУЕТСЯ      | Ссылки на загружаемые протоколы  |
| Сценарий            | ТРЕБУЕТСЯ      | Фазы, определение scope, возврат |
| Definition of Ready | ТРЕБУЕТСЯ      | Preconditions запуска цикла      |
| Definition of Done  | ТРЕБУЕТСЯ      | Postconditions завершения цикла  |
| Сводка              | ТРЕБУЕТСЯ      | Что выводить после завершения    |

### Вводный абзац

ТРЕБУЕТСЯ содержать:

- Роль: «Ты — оркестратор цикла **<фазы>**».

### Общие документы

ТРЕБУЕТСЯ содержать ссылку на runtime-протокол:
[orchestrator-protocol.md](orchestrator-protocol.md).

### Сценарий

Секция-обёртка для описания поведения цикла. Содержит подсекции:

- **Фазы** (ТРЕБУЕТСЯ): таблица с колонками Фаза, Исполнитель, Reviewer.
- **Определение scope** (ТРЕБУЕТСЯ): маппинг типа задачи на путь к файлам,
  правила для новых файлов (если применимо).
- **Возврат к ранним фазам** (многофазные циклы): каким агентам ЗАПРЕЩАЕТСЯ
  редактировать артефакты ранних фаз (с обоснованием), типичные сценарии возврата.

#### Подсекция «Фазы»

Таблица с колонками: Фаза, Исполнитель, Reviewer.

```markdown
| Фаза   | Исполнитель    | Reviewer       |
| ------ | -------------- | -------------- |
| <name> | `<agent-name>` | `<agent-name>` |
```

Каждая фаза — пара «исполнитель → reviewer». Порядок фаз определяет
последовательность выполнения цикла.

#### Подсекция «Определение scope»

Правила определения целевых файлов на основе запроса пользователя.
ТРЕБУЕТСЯ указать:

- Маппинг типа задачи → путь к файлам.
- Правила для новых файлов (если применимо).

### Definition of Ready

DoR описывает preconditions запуска цикла. Типичные пункты:

- Требования пользователя уточнены.
- Scope определён и файлы доступны.
- Пайплайн валидации проходит (если применимо).

### Definition of Done

DoD описывает postconditions завершения цикла. Типичные пункты:

- Все reviewer-агенты прошли с `verdict: pass`.
- Пайплайн валидации проходит после изменений.
- Решение прошло валидацию у пользователя.
- Сводка результатов выведена.

### Секция «Сводка»

Определяет что ТРЕБУЕТСЯ вывести после завершения цикла.

## Связь skill с агентами

- Имена агентов в таблице фаз SKILL.md ДОЛЖНЫ совпадать с `name` в YAML frontmatter определений агентов.
- Каждый агент из таблицы фаз ДОЛЖЕН иметь определение в `.agloom/agents/<agent-name>.md`.
- `artifacts` исполнителя одной фазы ДОЛЖЕН соответствовать `scope` reviewer той же фазы.
- В многофазных циклах: `artifacts` фазы N ДОЛЖНЫ соответствовать `scope` фазы N+1.

## Возврат к ранним фазам

Правила возврата описываются в подсекции «Возврат к ранним фазам»
секции «Сценарий» (см. выше).
