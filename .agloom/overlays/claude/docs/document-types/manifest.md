# type: manifest

**Назначение.** Реестр компонентов системы. Содержит перечень
компонентов, их расположение и связи. Manifest — стабильный документ:
отражает структуру системы, а не её текущее состояние.

Аналитические артефакты (результаты валидации, метрики, аудиты)
в manifest не включаются, потому что они устаревают при каждом
изменении и создают ложное чувство актуальности.

## Front matter

Общие поля — см. `index.md` → «Документационный front matter».

Поля `status` и `maps_to` неприменимы.

## Структура

ТРЕБУЕТСЯ:

- Перечень компонентов с расположением (файловые пути) и кратким описанием.

РЕКОМЕНДУЕТСЯ:

- Визуализация связей между компонентами (граф, диаграмма).

## Валидация

| #   | Правило                                                        | Тип           |
| --- | -------------------------------------------------------------- | ------------- |
| M1  | Front matter содержит `type: manifest`                         | Структурное   |
| M2  | Отсутствует поле `status`                                      | Структурное   |
| M3  | Все файловые пути в документе разрешаются в существующие файлы | Структурное   |
| M4  | Не содержит аналитических/временных данных (метрики, аудиты)   | Семантическое |
