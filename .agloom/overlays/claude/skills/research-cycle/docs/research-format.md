# Формат исследования

Методология, структура и критерии качества исследовательских документов (`type: research`).

## Методология (6 фаз)

| #   | Фаза                  | Содержание                               |
| --- | --------------------- | ---------------------------------------- |
| 1   | Постановка вопроса    | Проблема, цель, границы, контекст        |
| 2   | Определение критериев | Критерии оценки ДО анализа объектов      |
| 3   | Сбор данных           | Поиск объектов анализа (>= 3)            |
| 4   | Анализ                | Оценка каждого объекта по критериям      |
| 5   | Синтез                | Сравнительная таблица, ключевые паттерны |
| 6   | Обоснование           | Выводы с аргументацией                   |

**Критическое правило**: фаза 2 ТРЕБУЕТСЯ завершить до фазы 3.
Это защита от anchoring bias.

### Стратегия сбора данных (фаза 3)

ТРЕБУЕТСЯ обеспечить диверсификацию источников по категориям:

- Академические (arXiv, ACM, IEEE) — минимум 2 при наличии.
- Официальная документация провайдеров — минимум 2.
- Блоги и сообщество — минимум 2.

СЛЕДУЕТ применять snowball sampling: после первого раунда поиска проверить
ссылки найденных источников на пропущенные цитирования.

## Структура документа

### Обязательные секции

1. **Front matter**: `type: research`, `summary`, `description`, опционально `relates`.
2. **Заголовок**: `# Исследование: <тема>`.
3. **Дата**: дата проведения.
4. **Контекст исследования**: проблема, мотивация, цель, границы.
5. **Аналитическая часть**: объекты анализа с детальной оценкой по критериям.
6. **Заключение**: сводка решений с обоснованием.

### Рекомендуемые секции

- **Критерии оценки** — определение критериев до анализа — обязательный шаг методологии (фаза 2).
- **Сравнительная таблица** — все объекты анализа × все критерии.
- **Обоснование выбранного подхода** — развёрнутая аргументация.
- **Практические примеры** — шаблоны, code-блоки, чеклисты, когда тема
  подразумевает прикладное использование результата.
- **Источники** — ссылки на внешние материалы.

### Требования к объектам анализа

- Минимум 3 объекта анализа. Защита от false dichotomy.
- Каждый объект содержит **минимум 1 плюс** и **минимум 1 минус**.
- Каждый объект описывает контекст применимости: когда оправдан, когда нет.
- Глубина анализа пропорциональна доступности данных. Значительная
  асимметрия (> 2x по объёму) ТРЕБУЕТСЯ обосновать явно.

### Размер и организация документа

Исследования регулярно загружаются в контекст AI-агентов как справочный
материал. Рекомендуемый максимум — **250 строк** на файл.

Если суммарный объём объектов анализа превышает 400 строк, исследование
ТРЕБУЕТСЯ разделить на директорию:

```text
docs/researches/<research-name>/
  RESEARCH.md                # индексный файл (до 250 строк)
  <category>/                # per-object файлы
    <object-name>.md         # (до 250 строк каждый)
```

- **`RESEARCH.md`** (до 250 строк) — контекст, критерии, ссылки на
  per-object файлы, сравнительная таблица, выводы и рекомендации.
- **Per-object файлы** (до 250 строк каждый) — детальный анализ по критериям,
  плюсы/минусы, источники конкретного объекта. Размещаются в подпапке
  с семантическим именем (например, `agents/`, `alternatives/`).

Каждый per-object файл содержит `relates` ссылку на `RESEARCH.md`.

Исследования, помещающиеся в один файл (до 250 строк), остаются
файлом без директории: `docs/researches/<research-name>.md`.

Принципы организации:

- **SRP** — индекс изменяется при изменении стратегических выводов;
  per-object файл — при обновлении данных конкретного объекта.
- **ISP** — агент, работающий с одним объектом анализа, загружает только
  его файл, а не весь документ.

### Тон и стиль

Исследования пишутся в третьем лице. Обращения ко второму лицу ЗАПРЕЩАЮТСЯ.
Академический стиль: формальная лексика, нет сленга и разговорных выражений.

## Рубрика качества (D1–D6)

Reviewer оценивает по шкале 1–5. Пороги приёмки: D1 >= 3, D2-D5 >= 4, D6 >= 3.

### D1. Структура

Логичность иерархии заголовков, навигация, порядок секций.

### D2. Полнота

Все обязательные секции, >= 3 объектов анализа с плюсами и минусами, сводная таблица,
выводы с аргументацией, источники.

### D3. Объективность

Пропорциональная глубина анализа всех объектов (асимметрия > 2x обоснована),
наличие минусов у каждого объекта, отсутствие когнитивных искажений
(см. «Индикаторы bias»).

### D4. Техническая корректность

Фактическая верность утверждений, корректность примеров, логичность выводов.

### D5. Обоснованность решения

Трассируемость аргументов к данным анализа, непротиворечивость с данными
сравнительной таблицы.

### D6. Оформление

Корректный markdown, front matter, консистентный стиль.

## Индикаторы когнитивных искажений (B1–B7)

| #   | Искажение        | Индикатор проблемы                                   |
| --- | ---------------- | ---------------------------------------------------- |
| B1  | Anchoring        | Первый объект описан значительно подробнее остальных |
| B2  | Confirmation     | У объекта анализа нет минусов                        |
| B3  | Bandwagon        | «Все используют X» как единственный аргумент         |
| B4  | Strawman         | Объект анализа описан карикатурно                    |
| B5  | Sunk cost / IKEA | «Мы уже используем X» как довод                      |
| B6  | Optimism         | Отсутствие ограничений / рисков                      |
| B7  | Survivorship     | Только успешные примеры, неудачи проигнорированы     |

## Типы замечаний (finding types)

| Тип                | Описание                           |
| ------------------ | ---------------------------------- |
| Неполнота          | Отсутствует обязательный элемент   |
| Необъективность    | Индикатор когнитивного искажения   |
| Логическая ошибка  | Нарушение логики аргументации      |
| Фактическая ошибка | Неверное утверждение               |
| Противоречие       | Несогласованность внутри документа |
| Структура          | Нарушение размера или организации  |
| Формат             | Проблема оформления                |
