# Типы операций: cli

Операции CLI-инструмента — команды, переиспользуемые процедуры
и расширения существующих команд.

## cli:command

CLI-команда — обработка вызова из командной строки.
Одна команда = одна операция = одна единица спецификации.

### Шаблон

```text
### <Название команды>

`<binary> <command> [--flag <value>] [<positional>]` — описание.

**Аргументы:**

- `--flag` (тип, обязательно) — описание.
- `--option` (тип, опционально, default: значение) — описание.
- `<positional>` (тип, обязательно) — описание.

**Поведение:**

1. <Шаг — одно наблюдаемое действие>.
2. <Шаг>.

**Расширения:**

1a. <Условие> → <сообщение>; exit code <N>.

**Вывод:**

<Шаблон вывода в stdout.>

**Exit codes:**

- `0` — условие.
- `1` — условие.
```

### Аргументы

Параметры командной строки. Виды аргументов:

- **Именованные флаги** — `--adapter <value>` или `-a <value>`.
  Указывать тип, обязательность, значение по умолчанию.
- **Булевы флаги** — `--force`, `--verbose`.
  Тип `boolean`. Значение по умолчанию `false`, если не указано иное.
- **Позиционные аргументы** — `<path>`.
  Указывать тип, обязательность. Позиционные аргументы описываются
  в угловых скобках.

Если команда не принимает аргументов — указать «Нет аргументов».

Обязательность и типы — по общим правилам
(см. [Нотация обязательности](../spec-format.md#нотация-обязательности)).

### Поведение и Расширения

По общим правилам (см. [Поведение](../spec-format.md#поведение), [Расширения](../spec-format.md#расширения)).

Специфика CLI: результат расширения ДОЛЖЕН включать exit code, если
расширение приводит к завершению процесса. Формат:
`→ <сообщение или действие>; exit code <N>`.

### Вывод

Шаблон вывода в stdout. Правила:

- Fenced code block с языком `text`.
- Плейсхолдеры в `{фигурных скобках}`.
- При наличии нескольких вариантов вывода (успех, ошибка, пустой результат)
  каждый вариант — отдельный code block с условием перед ним.
- Если команда не производит вывода — указать «Нет вывода».

### Exit codes

Перечисление exit codes с условиями. Стандартные значения:

- `0` — операция завершилась успешно.
- `1` — ошибка (невалидный аргумент, ошибка выполнения,
  неизвестная команда/адаптер).

Если exit code определяется по совокупности условий (например,
`1` при ошибке в любом из шагов), условие ДОЛЖНО быть описано явно.

### Пример

```text
### Команда clean

`agloom clean --adapter <adapterId>` — удаляет сгенерированные
файлы для указанного адаптера.

**Аргументы:**

- `--adapter` (string, обязательно) — идентификатор адаптера из реестра.

**Поведение:**

1–3. Resolve Adapter
(см. `adapter-registry-ext.md` § Процедура Resolve Adapter).
4. Рекурсивно удалить все файлы и директории
   в `<projectRoot>/<entry.targetRoot>/`.
5. Удалить каждый файл из `entry.targetFiles`.
6. Сформировать `CleanOutcome` с `removedCount`, `errors`.

**Расширения:**

4a. Директория `targetRoot` не существует → `removedCount: 0`,
не является ошибкой.

4b. Ошибка удаления файла (EACCES и т.п.) → добавить сообщение
в `errors`, продолжить с оставшимися файлами.

**Вывод:**

При успехе:

    Cleaning for {adapterId}...
      ✓ {removedCount} files removed

    Done.

При наличии ошибок:

    Cleaning for {adapterId}...
      ✗ {errors[0]}

    Done. {removedCount} files removed.

**Exit codes:**

- `0` — успех.
- `1` — ошибка удаления или неизвестный адаптер.
```

## cli:procedure

Переиспользуемая процедура — последовательность шагов, общая
для нескольких команд. Определяется один раз и ссылается из команд
для устранения дублирования.

Процедура НЕ является самостоятельной CLI-командой. Она не имеет
собственного вывода и exit codes — это ответственность команды,
вызывающей процедуру.

### Шаблон

```text
### <Название процедуры>

<Описание назначения и контекста переиспользования.>

**Вход:**

- `param` (тип, обязательно) — описание.

**Поведение:**

1. <Шаг>.

**Расширения:**

1a. <Условие> → <результат>.

**Результат:**

<Что процедура возвращает / какие значения делает доступными.>
```

### Вход

Плоский список параметров. Обязательность и типы — по общим правилам.
Если процедура не принимает параметров — указать «Нет входных параметров».

### Результат

Описание значений, которые процедура делает доступными
для вызывающей команды. Формат: перечисление именованных значений с типами.

### Ссылки из команд

Команда, использующая процедуру, ссылается на неё в секции «Поведение»,
заменяя шаги процедуры одной строкой:

```text
**Поведение:**

1–3. <Название процедуры>
(см. `<путь к спеке>` § <Название процедуры>).
4. <Собственный шаг команды>.
```

Нумерация шагов в команде ДОЛЖНА учитывать шаги процедуры.
Если процедура содержит 3 шага и команда ссылается на неё
как на шаги 1–3, собственные шаги команды начинаются с 4.

### Пример

```text
### Процедура Resolve Adapter

Общая процедура разрешения адаптера для команд,
принимающих аргумент `--adapter`.

**Вход:**

- `--adapter` (string, обязательно) — идентификатор адаптера из реестра.

**Поведение:**

1. Распарсить аргумент `--adapter` из командной строки.
2. Найти запись в реестре адаптеров с `id`,
   совпадающим со значением `--adapter`.
3. Определить `projectRoot` как текущий рабочий каталог
   процесса (`process.cwd()`).

**Расширения:**

1a. Аргумент `--adapter` не указан → отобразить сообщение
об обязательности аргумента; exit code 1.

2a. Запись не найдена → отобразить сообщение
`"Unknown adapter: {value}."`; exit code 1.

**Результат:**

- `entry` (AdapterRegistryEntry) — запись адаптера из реестра.
- `projectRoot` (string) — абсолютный путь к корню проекта.
```

## cli:command-ext

Расширение существующей команды — добавление флагов, шагов
или изменение поведения команды, определённой в другой спецификации.

Расширение НЕ является самостоятельной операцией. Оно описывается
внутри спецификации, которая добавляет новую возможность, и ссылается
на исходную команду. Это следует OCP: исходная спека не модифицируется,
новая спека расширяет поведение.

### Шаблон

```text
### Расширение команды <name>

Команда `<name>` (см. `<путь>` § <секция>) расширяется.

**Новые аргументы:**

- `--flag` (тип, опционально) — описание.

**Новые шаги:**

После шага <N>:
<N+1>. <Описание нового шага>.

**Изменения в выводе:**

<Описание изменений или новый шаблон вывода.>

**Изменения в exit codes:**

<Описание изменений.>
```

### Правила

- Каждая подсекция (Новые аргументы, Новые шаги, Изменения в выводе,
  Изменения в exit codes) включается только при наличии изменений.
- Ссылка на исходную команду ТРЕБУЕТСЯ для трассируемости.
- Если расширение изменяет существующий шаг (а не добавляет новый),
  указать номер шага и описать изменение.

### Пример

```text
### Расширение команды transpile

Команда `transpile` (см. `cli.md` § Команда transpile) расширяется
шагом provider overlay.

**Новые шаги:**

После шага 7 (Agents):
8. Выполнить шаг provider overlay
   (см. § Обнаружение overlay-файлов, § Копирование overlay-файлов).

**Изменения в выводе:**

Шаг overlay отображается после остальных транспилерных шагов:

    ✓ Overlay       4 files

Если `.agents/overlays/<adapterId>/` не существует:

    ✓ Overlay       0 files

**Изменения в exit codes:**

Exit code учитывает ошибки шага overlay наравне
с остальными шагами.
```
