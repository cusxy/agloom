# Типы операций: library

Операции библиотеки/SDK — публичный API модуля, поставляемого как пакет.

## Структура спецификации

Спецификация библиотеки — документ, содержащий операцию `library:initialization`
(обязательно) и одну или несколько операций `library:method`. Если библиотека
владеет ресурсами, требующими очистки (соединения, таймеры, файлы), один из
методов описывает завершение работы (например, `close()`).

```text
## <Название библиотеки>

<Краткое описание назначения и области применения.>

### Инициализация         ← library:initialization

### <Название метода 1>   ← library:method
### <Название метода 2>   ← library:method
```

## library:initialization

Создание экземпляра библиотеки — конструктор или фабричный метод.

### Шаблон

```text
### Инициализация

`new ClassName(config)` или `ClassName.create(config)`.

**Вход:**

- `param` (тип, обязательно) — описание.

**Поведение:**

1. <Шаг>.

**Расширения:**

1a. <Условие> → <исключение>.

**Результат:**

Экземпляр `ClassName`.
```

### Вход

Конфигурация экземпляра: ключи API, URL, таймауты, опции.
Обязательность и типы — по общим правилам.

### Результат

Всегда "Экземпляр `ClassName`". Исключения описываются в Расширениях.

### Пример

```text
### Инициализация

`new ExchangeClient(config)`.

**Вход:**

- `apiKey` (string, обязательно) — ключ API.
- `baseUrl` (string, опционально, default: "https://api.exchange.com") — базовый URL.
- `timeout` (number, опционально, default: 5000) — таймаут запроса в мс.

**Поведение:**

1. Валидировать формат `apiKey`.
2. Создать HTTP-клиент с указанным `baseUrl` и `timeout`.

**Расширения:**

1a. `apiKey` пуст или не соответствует формату → `ConfigError("Invalid API key")`.

**Результат:**

Экземпляр `ExchangeClient`.
```

## library:method

Публичный метод библиотеки — одна операция, доступная потребителю.

### Шаблон

```text
### <Название метода>

`instance.method(params)` — описание.

**Вход:**

- `param` (тип, обязательно) — описание.

**Поведение:**

1. <Шаг>.

**Расширения:**

1a. <Условие> → <исключение или значение>.

**Результат:**

`<тип>`.

- `field` (тип) — описание.
```

### Вход

Плоский список параметров метода. Обязательность и типы — по общим правилам.
Если метод не принимает параметров — указать "Нет входных параметров".

### Результат

Тип возвращаемого значения. Если метод возвращает объект — список полей с типами
через отступ. Если метод не возвращает значения — `void`.

Исключения описываются в Расширениях, не в Результате.

### Пример

```text
### Получение текущего курса

`client.getRate(pair)` — возвращает текущий курс валютной пары.

**Вход:**

- `pair` (string, обязательно) — валютная пара (например, "BTC/USDT").

**Поведение:**

1. Валидировать формат `pair`.
2. Отправить GET-запрос к `/ticker/{pair}`.
3. Преобразовать ответ в объект `Rate`.

**Расширения:**

1a. Формат `pair` невалиден → `ValidationError("Invalid pair format")`.
2a. Сервер вернул 404 → `PairNotFoundError`.
2b. Сервер не ответил в пределах `timeout` → `TimeoutError`.
2c. Сетевая ошибка → `ConnectionError`.

**Результат:**

`Rate`.

- `pair` (string) — валютная пара.
- `bid` (string) — цена покупки.
- `ask` (string) — цена продажи.
- `timestamp` (ISO 8601) — время котировки.
```
